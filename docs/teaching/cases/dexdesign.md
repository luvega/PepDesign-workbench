# 07｜DexDesign／OSPREY3：准备 D/L 复合物并规划能量搜索

**method ID：**`dexdesign`。**任务：**从 8GAJ 准备输入，规划小范围 D 肽搜索。**状态：**教材已编写，prepared D/L 输入、构象库、资源和小搜索仍待准备及验收；没有本机能量结果。

## 阶段一：完整示范

### 本例要解决什么问题

固定来源起点为 **8GAJ：E. coli LptA 与 Podisus maculiventris thanatin 的晶体复合物**。LptA 为 A/C 链、132 aa；thanatin 为 B/D 链、21 aa。RCSB 两种 polymer entity 都登记为 `polypeptide(L)`；原始结构是 **L/L 起点，不是 prepared D 肽／L 受体输入**。

OSPREY 固定版 D/L 脚本的注释提到 `8gaj-trim...`，却没有提供这份 prepared 文件，也缺少完整的裁剪、链配对、骨架匹配和化学准备记录。因此，本例先讲清怎样准备输入；注释中的文件名不能当作现成输入。

| 步骤 | 本例怎样做 | 为什么 |
|---|---|---|
| 1 目标 | 从公开结构准备 D/L 候选，限定搜索范围 | 搜索依赖已准备好的输入，不能从任意 PDB 一步得到可信 D 肽 |
| 2 输入确认 | 核实真实结合链对、构建体、二硫键与末端，保留原件 | 多链条目不能按字母邻接猜结合链对 |
| 3 设置条件 | 准备 D/L 骨架、D 构象库，定义柔性位点和搜索范围 | 反射原始 L thanatin 后，还需检查新体系是否合理 |
| 4 原生运行 | 教师审阅脚本和作业设置后，执行小范围搜索 | 原脚本面向集群，还需确认 CPU、内存和 JVM 条件 |
| 5 审阅结果 | 分别检查输入化学、搜索范围、数值状态和结构 | 有能量值、进程结束、搜索收敛是不同状态 |
| 6 决定下一步 | 先修复输入或未完成的搜索，再讨论候选 | 有限搜索的计算结果不能直接给出实验 KD 或抗菌活性 |

### 原生准备与执行说明

本阶段尚无可执行的 prepared 输入。后续按下面顺序准备并记录：

1. 在私有目录保存 8GAJ 来源和结构版本。结合接触关系及生物学信息，确认 LptA／thanatin 链对和截取范围；记录保留原子、二硫键、端基、补原子和质子化处理。
2. 记录所选 D/L 路线中的镜像和骨架检索过程。若用 MASTER，保存检索库、查询和选中匹配；说明返回后怎样得到 L 受体＋D 肽。仅反射原 L 肽，不能保证保留结合几何。
3. 检查最终手性、连接和残基对应关系。完成原生 `DL_preprocess.py` 等步骤要求的准备，保留各阶段文件，得到可追溯的 prepared 输入。
4. 修改 `DL.py`、`Confspace_Combiner.py`、`ccsKstar.py` 文件内的设置及其生成作业。核对 prepared 目录、引擎、D 构象库、柔性位点、CPU、内存和时间额度；限定小范围后再执行。
5. 保存构象空间、运行状态、数值界限、收敛信息和 ensemble。核对结构及计数后，决定下一步。

[搜索准备 JSON](../../../configs/dexdesign/search-inputs.template.json)只供人工记录。原生脚本没有 `python DL.py --pdb ... --weights ...` 这种统一入口，也不需要神经网络 checkpoint。脚本中写死了部分大集群资源设置，后续要按本机资源修改，目前资源仍待盘点。

### 修改指南

| 分类 | 原生准备／设置 | 自己项目怎样处理 |
|---|---|---|
| 必须准备 | prepared 复合物、骨架来源、L/D 标识 | 实际有效的化学和手性输入，不能用原始 L/L 文件替代 |
| 必须定义 | D 构象库、柔性／可变位置、二硫键等约束 | 与本轮化学问题和搜索空间对应 |
| 必须修改 | 引擎、目录、线程、内存、作业/墙钟设置 | 使用教师核实的资源，不复制原集群路径 |
| 可以调整 | 位点数量与构象空间大小 | 改变搜索范围后，说明新旧结果能否比较及原因 |
| 不能照抄 | `8gaj-trim` 注释、未核实的链对/端基 | 注释不是输入成品或准备证明 |

### 合成教学记录：怎样审阅

人工给定：A 得到较低能量数值，但 prepared 文件不能追溯、搜索达到资源上限而截断；B 的输入可追溯，并在声明的较小空间内完成搜索。两者搜索空间不同；没有真实数值、结构或收敛文件。

先查 A 的输入来源和搜索状态，暂不按低能量值选它。B 的结果只能用于其已声明搜索范围内的计算比较；两者搜索空间不同，不能直接判断 B 优于 A，也不能换算成实测结合常数。

如果还没有有效 prepared D/L 输入，下一步应先准备输入。能说明这一决定和理由，也算完成本阶段任务。

**自我解释：**原始 8GAJ 为何不能当成 D/L 已准备？为什么有 GPU 不能保证本路线能跑？为什么更低能量不自动胜过空间和收敛条件不同的另一结果？
