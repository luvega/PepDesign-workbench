# 研究任务卡：从问题到原生方法

复制到自己的课题目录后填写，可删去不适用的问题。本卡用来说明研究计划，**不能直接作为统一程序输入或 Baker CLI request schema**。环境准备和实际运行另作记录。

## 1. 我在设计什么

- 当前研究问题：
- 设计对象：肽／蛋白 binder／环肽／其他：
- 结合对象或结构目标：
- 现在需要作出的决定：
- 出现什么结果时，我会改变决定：

写清肽是要设计的候选，还是要结合的靶标。设计无靶标单体环肽时，写折叠或几何目标即可。

## 2. 我实际有什么输入

- 来源与定位：PDB、上游文件、文献／用户确认记录及具体位置：
- 物种、构建体、突变、组装体与状态：
- 受体链、候选链及残基编号规则：
- 参考配体／参考肽的角色：定义位点、结构参照或其他：
- 已知末端、环化、二硫键、手性和保留组分：
- 原件与工作副本位置；版本／哈希记录所在处：
- 不知道的内容及它影响哪一步：

分别注明数据库全长序列、实验构建体和 PDB 可见片段。文件处理后，重新核对链和编号。

## 3. 怎样把要求写进原生配置

选定 method ID（通常 1—2 个）：

| 条件或偏好 | 原因 | 必须／偏好／开放／未知 | 对应字段或操作 | 强制指定／引导／未设置 | 输出后怎样检查 |
|---|---|---|---|---|---|
| 在此填写自己的第一项条件 | | | | | |

只填相关条件。长度、hotspot、口袋、contig、环化和手性，有的可由输入强制指定，有的只能引导生成。未设置的要求，要说明是方法不支持，还是本次未采用。保留零值、排除条件和“不适用”；未知内容不要猜填。无法检查的性质写“未验证”。

## 4. 原生执行准备

- 方法源码与固定 commit：
- 对应案例和原生配置／函数／Notebook：
- 人工参数记录与真正程序输入分别是：
- 环境、模型与资源状态：待盘点／部分就绪／已核实，依据：
- 本轮输入、输出目录，以及与前轮的关系：
- 计划规模和停止条件；未确定时写待定：
- 原生运行记录位置：

用[运行记录模板](../../../configs/run-record.template.json)保存实际命令、环境、输入摘要和产物，本卡只需指向该记录。更改准备规则或输入时，另建一轮目录，保留原件。

## 5. 结果与下一步

- 结果来源：上游报告／合成教学记录／本项目实跑：
- 实际运行状态与原生过滤状态：
- 得到了什么：序列／骨架＋序列／全原子复合物／能量搜索等：
- 哪些结果支持当前判断：
- 有哪些冲突、异常或尚未检查的问题：
- 当前决定及理由：推荐／小规模探索／修复／换方法／停止：
- 下一步准备比较什么，它能解决哪个问题：

可以没有推荐或探索候选。分别解释各项证据，不把不同方法的分数相加成“可信度总分”。若用对照调整过规则，要注明它参与了校准，不能再把同一对照算作独立验证。
