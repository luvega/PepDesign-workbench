# 个人项目迁移与提交模板

用本模板把公开案例改成自己的研究方案。完成相应练习后，选择 1—2 个适用方法，说明新输入、新配置和判断理由。更换靶标时，要重新准备输入。

## A. 我从哪个例子出发

- 所选案例／method ID／源码 commit：
- 原案例的设计对象、输入和回答的问题：
- 我的研究问题，以及保留这条路线的理由：
- 若方法不适用，我选择转向什么、为什么：

## B. 我的项目与原例有什么不同

| 项目 | 原例 | 我的输入或选择 | 需要重做的检查／仍然未知 |
|---|---|---|---|
| 受体或结构目标 | | | |
| 构建体、链、编号、状态 | | | |
| 位点来源或无位点理由 | | | |
| 长度、拓扑、手性和相关化学处理 | | | |
| 原生配置、模型文件和预期产物 | | | |

按需增删行。物种、糖链、pH 或末端与问题有关时再展开。对方法没有相应设置的要求，注明后续怎样处理和检查。

## C. 原生配置修改说明

- 必须改动的字段／操作及新值或待定原因：
- 保留原值的字段及依据：
- 只改一项条件的受控比较：
- 处理前后链／残基／原子对应记录：
- 本轮配置、后续运行记录和产物的私有目录：

先确认 JSON 是人工记录还是程序配置，再决定怎样使用；参数须来自原生接口。尚未实跑时，提交配置说明和计划检查的内容，运行状态写“未执行”。

## D. 我的结果审阅

| 项目 | 我真正检查了什么 | 结果／状态 | 可以支持的判断 | 不能支持或仍待检查的内容 |
|---|---|---|---|---|
| 输入与配置 | | | | |
| 产物类型，是否满足要求 | | | | |
| 原生评分／过滤／搜索状态 | | | | |

注明结果来自上游报告、合成教学记录还是本项目实跑。记录总尝试数和失败数，分别统计候选、轨迹、同一骨架的序列及实验样本。只有序列时无法验证三维手性；只有骨架时无法确认全原子界面。

## E. 决定下一步

写清当前决定和理由：哪些证据支持它，哪些冲突或缺失信息可能改变它。再提出一次后续比较，说明结果不同时你会怎样决定。推荐、保留少量候选探索、修复、换方法或停止，都可以是合理答案。

**学生提交清单：**

1. 一份自己的[研究任务卡](research-task-card.md)。
2. 修改后的原生配置或 API/Notebook 输入说明，附字段修改理由。
3. 一份运行记录；未执行时明确状态与所缺条件。
4. 结果审阅和下一轮决定，附可复查的来源或私有产物位置。

完整序列、结构、模型和日志在个人或课程服务器目录保存，不推入公开教材仓库。公开汇报可使用经确认可分享的摘要。

**提交前自查：**输入能否找到？方法是否支持所写条件？结果是否真的满足要求？失败和冲突是否记全？下一步要解决的问题是否明确？
